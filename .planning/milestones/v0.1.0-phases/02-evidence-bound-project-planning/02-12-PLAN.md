<objective>
Close the leaf-level honesty defects that let a bounded or partially-unreadable input be reported as a
confident complete answer, and reconcile the three declared contracts that contradict the code reading
them.

This plan owns the INPUT and OUTPUT bounds. Its sibling 02-13 owns making a bound VISIBLE to the user;
the two are complementary and deliberately separated by file ownership: nothing here touches
`src/core/evidence.ts`, `src/core/project-plan.ts`, `src/types.ts` or `src/format.ts`.

`depends_on: ["02-11"]` is an ORDERING edge, not a data one: this plan consumes nothing 02-11 produces and
its file set is disjoint from 02-11's. The edge exists because both plans run `npm run build` and then
`node --test dist/...` against the SAME `dist/` output tree, so under parallel execution one plan's build
can overwrite `dist/` in the middle of the other's test run — an intermittent failure attributable to
neither. Serializing them is the cheapest way to make that impossible. The one thing this plan does read
from 02-11 is the test total its summary recorded, which is the floor the `npm test` gates below use.

Purpose: `.gitignore` is repository-controlled, and today a single line longer than 1024 characters
inside an otherwise valid 500-pattern file makes every path beneath that directory undecidable. That is
fail-closed, and it is also total — the subtree becomes unscannable on the strength of one line the
parser could have simply reported. On the other end of the pipe, `serializeObservable` returns
`{ text, truncated }` explicitly so the byte budget is observable to the caller, and `print()` writes
`.text` and discards `.truncated`, shipping a JSON document cut mid-token with exit 0.

Output: an ignore parser that distinguishes "this file could not be read at all" from "one line was too
long", an output seam that refuses rather than truncates, byte budgets that are enforced in bytes, and
three declared contracts that say what the code does.
</objective>
