# 23-01: Governance Precedence Hierarchy

## Goal

Declare `alpha-aos-task` as the highest-priority task intake authority in `AGENTS.md` and harness instructions across all five harnesses, while preserving native shortcuts under alpha-AOS governance and preventing agents from silently bypassing user intake interviews.

## Context

- `23-CONTEXT.md` Decision D-01: Do not delete native shortcuts (`$gsd-quick`, `$gsd-debug`, etc.); establish an explicit precedence hierarchy where `alpha-aos-task` governs initial intake and path selection before shortcuts execute.
- Decision D-03: Bar bare `$gsd-quick` from bypassing research and discussion when non-trivial external tools or architectures are involved.

## Tasks

1. **Update `AGENTS.md`**:
   - Refactor the `## GSD Workflow Enforcement` block to define the two-layer governance:
     - **Layer 1 (Intake Authority)**: `alpha-aos-task` governs natural task requests and enforces path confirmation (Conversational GSD vs Autopilot).
     - **Layer 2 (Execution Shortcuts)**: `$gsd-quick`, `$gsd-debug`, and `$gsd-execute-phase` serve as downstream execution entry points under `alpha-aos-task` boundaries.
   - Bar agents from unilaterally selecting bare `$gsd-quick` to bypass user intake or required capability research.
2. **Update `skills/alpha-aos-task/SKILL.md`**:
   - Align skill intake rules with the precedence hierarchy, clarifying how native shortcuts transition into active GSD workflows once intake is confirmed.

   - Assert that native shortcuts remain present and documented.
