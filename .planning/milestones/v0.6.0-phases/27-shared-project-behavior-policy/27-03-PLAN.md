## Shared coordinator and recovery contract

All callers derive the lock from the resolved physical root and fixed filename, independent of stateRoot, harness or spelling alias. The fixed root-level lock avoids creating `.alpha-aos` on a stale first-create attempt. Acquire one exclusive-create handle with `wx` and restrictive mode, after rechecking the root and lock path proofs. The record binds schema kind/version, canonical root and exact root identity, random owner token, host/PID and operation/digest context; never policy bytes or credentials. One attempt only: EEXIST returns bounded contention. No internal polling/retries. A caller may explicitly retry once after the winner terminates; its reviewed digest is then stale if bytes changed.

Lock order is target → state, release state → target, for apply and rollback. Refuse mismatched/incomplete held contexts; never acquire target while already holding an unrelated state session. Release only the same exact lock-file identity and owner token; a replaced/malformed lock is retained and reported. A crash leaves the target lock and journal inspectable. Never unlink on age/PID alone. Recovery requires explicit operator review of canonical identity, token/journal disposition and absence of all live owners before archiving/removing the retained lock; existing state repair alone cannot authorize target unlock. No automatic stale-lock repair or new repair command is introduced. Local cooperative-writer exclusion is the supported guarantee; unprovable filesystem/exclusive-create capabilities are explicit refusals/limitations, not network-mount or hostile-editor compare-and-swap claims.
