<objective>
Make `catalog/packs/*.yaml` the single authority for pack predicates (D-05) and give the facts those
predicates name their own declared vocabulary, so that adding a pack AND adding most new facts both
stay out of TypeScript. Only the six bounded detector KINDS remain code.

Purpose: without the fact-vocabulary split, D-05 is only half true — a pack could be added in YAML and
would silently never match, because the fact it names has no detector. A pack that never matches is
indistinguishable from a pack whose evidence is genuinely absent, which is the exact failure DETC-03
exists to prevent.

Output: `schemas/fact-vocabulary.schema.json`, `catalog/facts.yaml`, a full-fidelity
`schemas/pack-catalog.schema.json`, a seven-file merging strict loader, and `test/pack-catalog.test.ts`.
</objective>

| Boundary | Description |

| `catalog/packs/*.yaml` + `catalog/facts.yaml` → loader | Repository-owned reviewed data, but parsed as managed documents so a duplicated key or an unregistered field is a refusal rather than an ambiguity. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-05 | Denial of Service | `patterns` in `catalog/facts.yaml`, `fileContent` facts | medium | mitigate | Every content-match pattern is declared in this repository-owned reviewed file and never read from the scanned project; plan 02-06 caps input length before matching. |
