# 24-02: Harness Role Receipt Re-Probing & CLI `--probe` Integration

## Goal

Provide an automated, atomic re-probe recovery path (`reprobeHarnessRoleReceipt` and CLI `--probe` flag on `task doctor` and `task start`) when a harness binary updates on disk and triggers `binarySha256` or version drift (`BUG-02`).

## Context

- `24-CONTEXT.md` Decision D-03: When `agy.EXE` or another harness updates (e.g. `1.4.0` → `1.4.2`), operators must be able to pass `--probe` to `alpha-aos task doctor --probe` or `alpha-aos task start <contract.json> --probe` to re-verify the binary hash and CLI version and atomically update `~/.alpha-aos/receipts/harnesses/<harness>-<role>.json`.

## Tasks

1. **Add Receipt Re-Probe Functions (`src/adapters/task-receipts.ts`)**:
   - Implement `reprobeHarnessRoleReceipt(harness, role, receiptsRoot, options)` to resolve the current binary, compute `computeBinarySha256`, run `probeLaunchVersion`, and atomically write the updated `HarnessRoleReceipt`.
   - Support `autoReprobeOnDrift?: boolean` in `ReadReceiptOptions` so callers opting into `--probe` automatically refresh drifted receipts during `readHarnessRoleReceipt`.
2. **Propagate `probe` Option Through Role Verification (`src/adapters/task-agents.ts`, `src/core/task-doctor.ts`)**:
   - Allow `reprobeOnDrift?: boolean` in `verifyRoleCapabilities`, `probeTaskAgentPair`, and `buildTaskDoctorReport`.
3. **Expose `--probe` in CLI (`src/cli.ts`)**:
   - Support `alpha-aos task doctor [--probe]` and `alpha-aos task start <contract.json> [--probe] [--apply]` to re-probe drifted or missing receipts before readiness assessment and task start.

## Verification

- `npm run check` passes.
- Unit tests verify that simulated binary upgrades (`1.4.0` → `1.4.2`) fail closed by default (`checkDrift: true`) and automatically recover and persist updated `binarySha256` + `version` when `reprobeHarnessRoleReceipt` or `autoReprobeOnDrift: true` (`--probe`) is used.
