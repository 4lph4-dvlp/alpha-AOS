먼저 module-local `BoundedStream`에 non-destructive snapshot을 추가한다. 현재 `finish(context)`는 `this.hash.digest("hex")`를 호출해 한 번만 쓸 수 있다. 살아 있는 session은 evidence를 여러 번 읽어야 하므로 `snapshot(context: RedactionContext): RedactedExcerpt`를 추가하고 그 안에서 `this.hash.copy().digest("hex")`를 쓴다(`src/core/mcp-proxy.ts`의 기존 `collectUpstreamStderr`가 이미 쓰는 방식). 기존 `finish`는 `snapshot`을 그대로 위임 호출하도록 바꿔 `runProcess`의 관측 가능한 동작을 바꾸지 않는다.

다음 상수를 추가하고 `DEFAULT_MAX_MESSAGE_BYTES`, `DEFAULT_MESSAGE_TIMEOUT_MS`를 export한다. `DEFAULT_MAX_MESSAGE_BYTES = 1024 * 1024` (1 MiB). MCP SDK 자체 기본값 `STDIO_DEFAULT_MAX_BUFFER_SIZE`는 `10 * 1024 * 1024`이므로 alpha-AOS는 의도적으로 더 좁게 잡는다. `DEFAULT_MESSAGE_TIMEOUT_MS = 60_000` — 현재 `src/core/mcp-fixture.ts`의 `waitFor` 60초 deadline과 같은 값이다. `DEFAULT_CLOSE_GRACE_MS = 2_000` (export하지 않음).

타입 두 개를 export한다. `ProtocolProcessSpec`는 `executable: string`, `args: readonly string[]`, `cwd: string`, `environment?: EnvironmentPolicy`, `timeoutMs?: number`, `maxOutputBytes?: number`, `maxMessageBytes?: number`를 갖는다. `timeoutMs`는 session 전체의 absolute ceiling이고 기본값은 `DEFAULT_TIMEOUT_MS`이며 리터럴 `0`은 "absolute ceiling 없음"을 뜻한다(장기 실행 proxy 전용). `maxOutputBytes`는 보관되는 redacted stdout/stderr evidence의 상한이고 기본값은 `DEFAULT_MAX_OUTPUT_BYTES`다. `maxMessageBytes`는 개행으로 끝나지 않은 stdout frame 하나의 상한이고 기본값은 `DEFAULT_MAX_MESSAGE_BYTES`다. `stdin` 필드는 없다 — protocol session의 stdin은 살아 있는 stream이다.

`ProtocolSession`은 다음을 갖는다. `send(message: unknown): void` — `JSON.stringify(message)`에 `"\n"`을 붙여 child stdin에 쓴다(MCP SDK `serializeMessage`와 동일한 framing). `onMessage(listener: (message: Record<string, unknown>) => void): void`. `waitFor(match: (message: Record<string, unknown>) => boolean, timeoutMs?: number): Promise<Record<string, unknown>>`. `evidence(): { stdout: RedactedExcerpt; stderr: RedactedExcerpt }`. `readonly closed: Promise<ProcessResult>`. `close(): Promise<ProcessResult>`.

`export async function openProtocolProcess(spec: ProtocolProcessSpec): Promise<ProtocolSession>`를 구현한다. `runProcess`와 같은 seam을 재사용한다: `isAbsolute(spec.executable)`가 거짓이면 `ProcessPolicyError("unsupported-executable", ...)`를 던지고, environment는 `materializeEnvironment(spec.environment)`로 만들고, redaction context는 `redactionForEnvironment(environment)`로 만든다. child는 `spawn(spec.executable, [...spec.args], { cwd, env, shell: false, windowsHide: true, detached: process.platform !== "win32", stdio: ["pipe", "pipe", "pipe"] })`로 띄운다.

stdout 처리가 이 task의 핵심이다. 들어오는 모든 chunk를 (a) evidence용 `BoundedStream(maxOutputBytes)`에 넣고 (b) pending frame buffer에 이어 붙인다. `/\r?\n/`로 잘라 완성된 줄만 소비하고, `{`로 시작하는 줄만 `JSON.parse`한다. 파싱된 object는 등록된 listener에게 전달하고 `waitFor`용 backlog에도 넣는다. 파싱되지 않는 줄은 개수만 세고 버린다 — 절대 raw로 노출하지 않는다.

**byte cap:** 개행이 오지 않은 pending frame의 byte 길이가 `maxMessageBytes`를 넘으면 그 buffer를 버리고 `outputCapped`를 참으로 표시한 뒤 `child.pid`에 대해 `killTree(pid, "SIGKILL")`을 호출하고 session을 `code: "output-cap"`으로 settle한다. 이것이 현재 `src/core/mcp-fixture.ts`의 `stdout += chunk` 잔여 buffer가 갖지 못한 유일한 성질이며, 이 gap의 실체다.

stderr는 `BoundedStream(maxOutputBytes)`에만 공급한다. 어떤 경로에서도 terminal로 다시 내보내지 않고 message 문자열에 이어 붙이지 않는다.

`closed`는 `ProcessResult`로 resolve한다 — 새 code를 만들지 말고 기존 `ProcessCode` union을 그대로 쓴다: 정상 종료 `"ok"`, 0이 아닌 종료 `"non-zero-exit"`, frame cap `"output-cap"`, absolute deadline `"timeout"`, spawn 실패 `"spawn-failed"`. `stdout`/`stderr` 필드는 settle 시점의 `snapshot(redaction)` 결과다.

`close()`는 idempotent하다: child stdin을 end하고 `DEFAULT_CLOSE_GRACE_MS` 동안 `close` event를 기다린 뒤 아직 살아 있으면 `killTree(pid, "SIGKILL")`을 호출하고 `closed`와 같은 `ProcessResult`로 resolve한다.

Task 1에서 만든 session에 나머지 boundary 계약을 붙인다.

`waitFor(match, timeoutMs = DEFAULT_MESSAGE_TIMEOUT_MS)`를 구현한다. 이미 backlog에 있는 message 중 `match`를 만족하는 첫 번째를 즉시 resolve하고, 없으면 새로 도착하는 message를 기다린다. 자체 deadline이 지나면 `ProcessPolicyError("timeout", ...)`로 reject한다. 이 reject의 message에는 coded outcome과 `evidence().stderr.sha256`의 앞 12자, `totalBytes`만 넣는다 — 누적된 child output을 문자열에 이어 붙이지 않는다. session이 이미 settle된 뒤의 `waitFor`는 settle된 code를 담은 `ProcessPolicyError`로 reject한다.

absolute deadline을 붙인다. `spec.timeoutMs`가 리터럴 `0`이 아니면 `setTimeout(..., timeoutMs)`을 걸고 `deadline.unref()`한 뒤 만료 시 `killTree(pid, "SIGKILL")`을 호출하고 `timedOut`을 참으로 표시해 session을 `code: "timeout"`으로 settle한다. `runProcess`의 deadline 처리와 같은 모양을 쓴다. `timeoutMs: 0`은 ceiling만 끄며 Task 1의 per-frame cap과 `close()`의 강제 종료에는 아무 영향이 없다.
