# Fix Windows Pi MCP Bridge Spawn EINVAL on `.cmd` shim (P-1C-1)

<objective>
Fix the `spawn EINVAL` error during `alpha-aos update --apply` or `alpha-aos install --apply` on Windows when installing the Pi MCP bridge (`mcp-bridge:pi`).

Purpose: On Windows systems where Pi Agent is installed via npm global shim (`pi.cmd`), invoking `pi` directly with `shell: false` triggers Node.js Windows CVE-2024-27980 spawn validation failure (`Error: spawn EINVAL`). `src/core/install.ts` must resolve `pi` through `resolveDirectLaunch` (unwrapping the `.cmd` shim to `node.exe <cli.js>`) matching the pattern already used in `src/core/mcp-fixture.ts` and other adapters.

Output:
- Fix in `src/core/install.ts`.
- Regression test in `test/install.test.ts`.
- Full verification: `npm run check`, `npm test`, and verifying `alpha-aos update --apply` completes successfully.
</objective>

<constraints>
- Use `resolveDirectLaunch` from `../adapters/capability-oracle.js` to unwrap interpreted shims.
- Keep direct executable behavior unchanged on POSIX platforms (Linux/macOS).
- Strictly adhere to GSD conventions, atomic commits, and verified build artifacts.
</constraints>
