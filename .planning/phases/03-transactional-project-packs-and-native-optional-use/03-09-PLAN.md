<assumption_delta_decision>
**Signal:** the deterministic detector fired once, on the word "Optional" in the phase title
("Native Optional Use"), family `optional`.

**Honest evaluation.** In the phase title that word describes optional *capabilities* — the domain's
existing core noun since PROJECT.md's opening paragraphs, where broadly useful capabilities are global
and evidence-matched ones are project-scoped. No required field became optional. On the detector's own
terms, that signal alone is `no-change`.

**But a real transition is present, and it is the one the checkpoint exists to catch.** CONTEXT.md D-11
introduces a SECOND and THIRD case for a noun that previously had one: a capability's *state*. Phase 2's
`PackState` was the whole answer to "what is the state of this pack". This phase adds a native-use axis
and a support axis beside it. That is the `pluralization` family arriving through a differently-named
door.

**Noun that is now primary:** **capability state**, the triple (deployment × native-use × support).

**Decision: `promote`.** A composite `CapabilityState` record becomes the primary value every renderer,
JSON consumer and later gate reads, and `PackState` is demoted to its `deployment` field. `PackState`'s
union is NOT modified — D-11 requires it untouched, and demotion-to-a-field is exactly that.

**Rationale.** Add-alongside would leave `PackState` primary with two siblings hanging off it, so a
consumer could read the deployment axis alone and get back the single misleading installed state CAPA-07
exists to forbid. The generalisation is only real if the general representation is the one you get by
default.

**Invariant test earned:** yes. A contract test asserts that no exported reconciliation surface returns a
bare deployment-axis value at the top level — the axis is reachable only through the composite. It is
Task 2's first behaviour.
</assumption_delta_decision>
