documentation capability and complete a meaningful read-only call. CAPA-02 requires multi-source research

a meaningful call looks like for each: the documentation server's identifier resolution returns a version
list, so a query carrying a version-scoped identifier is CAPA-01's version-sensitivity made structural.

Output: the reconciled expectation lists, an ordered-sequence matcher, and recorded proofs for both
capabilities on the pass-bar harness.
</objective>

it carried a version segment — never the identifier's full value and never the response body. Plan

declared, non-value-bearing metadata field rather than opening a general argument channel.

`countDistinctServers(observations)` is the fan-out judgement, expressed as a count of distinct research
servers touched for one ordinary lookup. RESEARCH.md's second-order note is the reason it is a count and
not a tool sequence: the discovery server itself also ships a fetch tool, so more than one reasonable
two-tool path exists and pinning one would fail a correct run.

Distinctness keys on server id alone, so repeated calls to one server collapse to a single touch. That
collapse is the load-bearing half of the same note: a run that searches and then fetches entirely on the
discovery server makes two calls and is a correct single-server run, and a count that added those two
together would report the phase's own recommended routing as fan-out. Two calls carrying two different
server ids stay two.
