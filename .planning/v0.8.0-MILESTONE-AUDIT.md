## 1. Executive Summary

Milestone v0.8.0 successfully designed, implemented, and unit-tested all 21 plans across all 5 phases. The core domain innovations—including the local tool records single source of truth (`~/.alpha-aos/tool-records/v1/`), Sigstore Rekor SET cryptographic verification, minimal structural compatibility adapters with pure upstream retirement, 4-tier lifecycle evidence tracking, reverse-order native adapter rollback, and bilingual migration guidance—are all in place and have passing unit suites.

However, the automated cross-phase integration check discovered **3 critical integration blockers** that break end-to-end upgrade and recovery flows in live execution:
1. **Owned Skills Source Hash Drift**: Edits to `skills/alpha-aos-control/SKILL.md` and `skills/alpha-aos-task/SKILL.md` in Plan 43-04 desynchronized `catalog/stack.lock.json`, causing `applyManagedInstall` to throw an unhandled error.
2. **CLI `update --apply` Verification Bypass**: `src/cli.ts` does not pass verification requests or barrier inputs to `applyLocalReleasePlan`, causing the verification barrier to be skipped and accepted tool transitions to be omitted from `tool-records/v1`.
3. **`resumeReleaseOperation` Store Acceptance Gap**: Resuming an interrupted operation updates the lifecycle event log but does not commit the accepted transition to the primary `tool-records/v1` store.

## 3. Detailed Cross-Phase Wiring Findings

### Finding 1 (Blocker): `catalog/stack.lock.json` Skill Hashes Out of Sync
- **Origin:** Plan 43-04 (commit `230ddfd`) edited `skills/alpha-aos-control/SKILL.md` and `skills/alpha-aos-task/SKILL.md`.
- **Break:** `catalog/stack.lock.json` was not re-locked with the new SHA-256 digests.
- **Symptom:** `test/owned-skills.test.ts` fails with `Error: Owned skill source hash mismatch for alpha-aos-control: expected a66debb..., got d40eea...`.
- **Resolution:** Recompute SHA-256 for both skill files and update `catalog/stack.lock.json`.

### Finding 2 (Blocker): CLI `update --apply` Verification Requests Omission
- **Origin:** `src/cli.ts:2101` calls `applyLocalReleasePlan({ packageRoot: root, planDigest, reviewedPlanToken: reviewedPlan })`.
- **Break:** Does not pass `candidateVerificationRequests`, `barrierInputs`, or `postcheckObservations`.
- **Symptom:** `update.ts` skips the pre-activation verification barrier, sets `verified: null`, leaves `acceptedTransitions: []`, and fails to advance accepted tools in `tool-records/v1`.
- **Resolution:** Wire candidate verification requests from the decoded reviewed release plan into `applyLocalReleasePlan` in `src/cli.ts`.

### Finding 3 (Blocker): `resumeReleaseOperation` Missing Tool Record Store Commit
- **Origin:** `src/core/release-recovery.ts:733-868`.
- **Break:** Appends `activated` and `postcheck-passed` events to the lifecycle log, but does not invoke `finishToolOperation(recordPlan, session, acceptedTransitions)`.
- **Symptom:** Resumed operations report `resumed: true, status: "accepted"`, but `resolveAcceptedToolRecord` fails to find the tool.
- **Resolution:** Add `toolRecordStore` commit logic to `resumeReleaseOperation`.
