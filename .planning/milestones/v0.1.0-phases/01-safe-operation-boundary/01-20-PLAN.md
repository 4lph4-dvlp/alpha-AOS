## Why the RED is observable on a non-macOS host

The runtime test at `test/process.test.ts:147` can only go red on darwin, so on its own it would leave this fix unverifiable until CI. Making the floor a pure function of the platform argument moves the declaration itself under test: `platformFloorEnvironment("darwin")` is callable from Windows and Linux and returns `[]` before the fix. That is a real failing test on an ordinary developer host, committed before the fix, which is what the TDD convention in this phase requires. The runtime exact-match test remains the authority for whether the declaration is *true*, and only the macOS CI leg can answer that.
