<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI Workflow (`ci.yml`) → Red-Main Guard (`red-main-guard.yml`) | `ci.yml` runs on PRs and push with read-only token permissions; `red-main-guard.yml` runs asynchronously only from default branch (`main`) after CI completion, isolating write permissions. |
| Candidate Staging Workflow → Main Baseline Query | `dependency-candidate.yml` queries the read-only GitHub API for completed baseline runs before modifying the candidate pull request. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-06 | Elevation of Privilege | .github/workflows/red-main-guard.yml | high | mitigate | Isolates `issues: write` to default-branch executions; PRs cannot trigger this workflow with write access. Defense-in-depth job condition checks `head_branch == 'main'`. |
| T-12-07 | Supply Chain / Tampering | scripts/ in npm release tarball | medium | mitigate | `audit-tarball.mjs` verifies that only allowlisted scripts are included and forbids test or development artifacts from leaking into production packages. |
| T-12-08 | Repudiation / False Gating | .github/workflows/dependency-candidate.yml | high | mitigate | Fails closed on indeterminate baseline, preventing unverified dependency candidates from appearing eligible. |
</threat_model>
