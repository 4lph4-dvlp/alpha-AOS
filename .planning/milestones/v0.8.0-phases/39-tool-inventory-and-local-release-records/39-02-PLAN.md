## Writer ownership contract

39-02-01은 각 durable 변경 전에 `writerLockPath(stateRoot)`의 현재 lock record를 다시 읽고 session의 operationId/token/planDigest와 일치하는지 확인한다. 기존 `assertOwned()`는 닫힘 여부만 검사하므로 디스크의 lock 소유권 검증을 대체하지 않는다. lock 교체·누락·token 불일치·상충 digest는 첫 event/다음 event 쓰기를 거부하며 token 값은 event/진단에 절대 포함하지 않는다. `test/tool-record-store.test.ts`에 live session 중 lock 교체와 중첩 session 재사용의 부정/정상 사례를 추가한다. 이 검사는 기존 writer-lock 자체의 전역 동작을 바꾸지 않고 새 store의 호출 경계에서 수행한다.
