that single line is what this plan replaces.

discriminator on the receipt envelope, and a suite that proves the write, the rollback, and both
refusals.

Create `src/core/project-pack-sync.ts` and wire ONE path from an approved artifact to bytes on disk.

`planProjectPackSync(options)` takes the same option bag `revalidateProjectPlan` takes plus `stateRoot`
and an optional `verifiedSourceRoot`, and returns a `ProjectPackSyncPlan`. It reads the reviewed
artifact through `readApprovedProjectPlan` — never by re-deriving a plan — and refuses when the read
result is `absent` or `unreadable`. It revalidates through `revalidateProjectPlan` and, when
`classifyPlanDrift` reports any drift, refuses with a `ComponentPlanError` of kind `plan-drift`
carrying both digests and the runnable re-approval command from `approvalCommand`. The set of targets
comes from the artifact's `targetPreState` entries whose `action` is `create` or `update`, filtered to
entries whose `packId` is in the artifact's `applicable` list. An entry whose `harness` has no
`PROJECT_SKILL_ROOTS` key is a `plan-incomplete` refusal naming the harness, exactly as
`removalAllowedRoots` already refuses.

Source bytes bind at review time: for each target call `resolvePackSource(lock, packId, skill)` to get
`sourceSha256`, read the file from `verifiedSourceRoot` when supplied and otherwise from the ECC
fixture operation plan the same way `planEccSkillOperation` does, and record both the read bytes'
sha256 and the locked `sourceSha256`. Because `PLAN_RENDERER_ID` is `ecc-skill/identity`, the target
hash equals the source hash — assert that rather than recomputing a render. Prove every path role in
one `proveOperationPaths` call using `requiredRolesForFileMutation()` and fold destinations, sources,
hashes, `stateRoot`, `allowedRoots` and the boundary code into one `reviewedDigest("project-pack-sync", …)`.

`packSyncAllowedRoots(canonicalRoot, targets)` returns the resolved absolute roots: one

`join(canonicalRoot, ...PROJECT_RECEIPT_DIRECTORY.split("/"))`. Derive it exactly the way
`removalAllowedRoots` derives its inverse; do not re-spell either constant.

`applyProjectPackSync(options)` re-plans, calls `assertPlanUnchanged`, then runs
`withComponentSession(reviewed, options.session, …)`. Inside the session, per target:
`assertUnchangedSincePlan` against the planned source proof; a source whose sha256 no longer equals the

`SKILL.md` writes and the per-pack receipt writes and pass it to a SINGLE `applyFileTransaction` call
with `stateRoot`, `packSyncAllowedRoots(...)` and the session. Return `{ operationId, written,
receipts, packs }` where `written` and `receipts` are relative POSIX paths.

The receipt document is `{ schemaVersion: 1, packId, producer: { name: PLAN_OWNER, version }, createdAt,
sourceHash, evidenceHash, targets: [{ harness, path, targetHash }] }` — `path` relative POSIX from the
canonical root, `sourceHash` the pack's locked source hash, `evidenceHash` the artifact's evidence
digest, `producer.version` the package version from the lock's ECC component. Serialize with
`JSON.stringify(value, null, 2)` and a trailing newline so a re-run produces byte-identical content.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository tree → alpha-AOS writer | `.alpha-aos/plan.json` is committed and arrives attacker-supplied on every clone |

| alpha-AOS writer → project filesystem | the only phase-3 surface that writes into a directory the user owns |
