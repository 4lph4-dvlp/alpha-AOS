## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local Store → Runtime Consumers | Consumers read accepted records from tool-record-store; unvalidated records could alter execution |
| Harness Configs → Doctor | Doctor inspects external configuration files and backup snapshots across harnesses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43-04 | Tampering | `resolveAcceptedToolRecord` in `src/core/tool-bindings.ts` | high | mitigate | Verify store integrity, sequence numbers, and hash matches in `verifiedEventDigests`; reject unverified or incomplete stores fail-closed without fallback. |
| T-43-05 | Denial of Service / Tampering | Consumer fallback bypass in `src/core/mcp.ts` | high | mitigate | Eliminate all try/catch fallback branches to static lock/pin files; ensure missing records result in deterministic rejection with explicit user remediation. |
| T-43-06 | Information Disclosure | `diagnoseToolRecordsAlignment` in `src/core/doctor.ts` | low | mitigate | Restrict doctor diagnostic messages to component names, version numbers, and sanitized relative paths; never print raw config text or credentials. |
| T-43-SC | Tampering | npm/pip/cargo installs | high | mitigate | Package legitimacy gate verified in RESEARCH.md: no new external packages installed; standard built-in modules used exclusively. |
</threat_model>
