# Fix multi-harness combined install plan-drift on shared skill roots (G-11-1)

<objective>
Resolve gap G-11-1: Allow multi-harness managed installs across targets that share skill destinations (such as `codex` and `pi` sharing `<home>/.agents/skills`) to complete without throwing `ComponentPlanError("plan-drift")`, and ensure subsequent dry-run and apply runs report all steps as CURRENT and byte-identical no-op.

Purpose: Requirement LIFE-01 / Gap G-11-1 currently blocks Phase 13 dependency promotion. In combined installs (e.g. `install --target codex,pi --apply` or 5-harness install), the first target writes the shared skill to disk, causing the second target's revalidation to detect disk modification during the transaction and reject it as drift.

Output: Fix in `src/core/install.ts`, regression tests in `test/owned-skills.test.ts`, verification via unit tests and probe.
</objective>

<constraints>
- Preserve `assertPlanUnchanged` strictness for independent/standalone sync operations.
- Maintain atomic rollback and transaction integrity: shared destinations must not accumulate duplicate journals or conflicting rollbacks.
- Keep `createManagedInstallPlan` preview step contracts: each requested target continues to report its owned-skill and ECC step in plan previews.
- On repeat/reconcile apply: zero applied items, zero operationIds, all steps current, byte-identical filesystem state.
</constraints>
