  <action>
Compute `inputsDigest` and `evidenceDigest` separately, because D-13 needs to tell them apart.
`inputsDigest` is sha256 over the sorted list of `(relative POSIX path, sha256 of bytes)` for every
file a detector actually read — it answers whether anything looked at changed. `evidenceDigest` is
sha256 over the normalized sorted fact set of ids, detected flags, versions and paths — it answers
whether the selection-relevant observations changed. Map `inputsDigest` onto the evidence envelope's
`sourceHash` field, whose description already names it as the digest of the canonical repository state
the evidence was derived from, and carry `evidenceDigest` in the plan artifact.

This resolves the apparent tension with D-07 rather than dodging it: D-07 forbids a PER-FACT file hash,
so an unrelated comment change disturbs no individual fact; the AGGREGATE input digest is a different
object and is exactly what the phase's full-input-and-target-digests deliverable asks for. A comment
change moves `inputsDigest` and leaves `evidenceDigest` alone, which is precisely the case D-13 wants
reported as re-approvable.

`planDigest` is `reviewedDigest` over the digestable view, so `ProjectCapabilityPlan` structurally
satisfies the reviewed-plan boundary interface and can reuse the existing drift helpers in plan 02-09
rather than growing a second mechanism.

Close all three determinism hazards, and add the standing net that catches a regression in any of them:
`createdAt` and the git branch/commit context are excluded BY CONSTRUCTION — the digestable view is its
own object literal built in one place, never the envelope with fields deleted. Every digested object is
built from one literal so insertion order cannot diverge between two code paths. Every array is sorted
before it is emitted or digested.

Digests are sha256 over UTF-8 bytes. Serialize with an explicit `"utf8"` encoding at every hash call

contains non-ASCII characters and assert the digests are stable across two runs on the host. Note in
the summary that cross-host Unicode normalization (a macOS NFD path versus a Linux NFC path naming the
same file) is NOT proven by a single-host run; that belongs to the Phase 7 three-OS matrix and must not
be claimed here.

Add the byte-stability test as the cheapest possible regression net for the whole DETC-04 stability
