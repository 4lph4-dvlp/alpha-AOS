## Design decision: what `--files` means, stated concretely

`scripts/run-tests.mjs` today self-enumerates `dist/test/*.test.js` and treats `process.argv.slice(2)` as flags only, so it cannot express the ten-file subset the CI step needs. The chosen shape:

- `--files` is a **terminal** argument: every argument after it is a compiled test file path. Flags come before it. A second `--files` token later in the list is just a path, and will fail the existence check.
- Without `--files`, behaviour is unchanged: self-enumerate `dist/test/*.test.js`, sorted, and fail loudly on the empty set.
- With `--files` and zero paths after it, fail loudly. An explicit empty set is a failure for the same reason the glob's empty set was.
- Named paths resolve against the repository root and keep the order given. The CI order is declared, not incidental, so it is not sorted.
- A named path that does not exist is a loud failure naming every missing path. This is strictly stronger than the shell glob it replaces: a suite that stops being compiled is red, not absent.

`INIT_CWD` is added to the scrubbed exact-name set. npm sets it on a lifecycle child and nothing else does; the current regex `^npm_(config|package|lifecycle)_` does not reach it, and a name the scrubber misses is the exact shape RC-5 already took once. `NODE` and `COLOR` are **deliberately not** scrubbed — they are not npm-namespaced, `NODE` is legitimately useful to a child, and widening the scrub set on a guess is how a repair becomes a second defect.

**단계 2 — `scripts/run-tests.mjs` 에 명시적 파일 부분집합을 가르친다.**

지금 이 스크립트는 `dist/test` 를 스스로 열거하고 `process.argv.slice(2)` 를 플래그로만 취급하므로 CI 가 필요로 하는 10-파일 부분집합을 표현할 수 없다. 다음 형태로 바꾼다. 위 `## Design decision` 절이 이 형태의 근거이고, 그 결정을 그대로 구현한다.

  - `process.argv.slice(2)` 에서 정확히 `--files` 토큰의 인덱스를 찾는다. 없으면 지금 동작 그대로다: `compiledTestFiles()` 로 `dist/test/*.test.js` 를 스스로 열거하고 정렬하고, 빈 집합이면 지금 있는 그 메시지로 exit 1.
  - 있으면 그 앞은 플래그, 그 뒤는 전부 파일 경로다 (`--files` 는 terminal). 새 모듈 로컬 함수 `namedTestFiles(argv)` 가 이 분리를 수행하고 `{ flags, files }` 를 돌려주게 한다.
  - `--files` 뒤에 경로가 하나도 없으면 loud failure 로 exit 1. 명시적 빈 집합도 빈 집합이며, glob 의 빈 집합이 실패였던 것과 같은 이유로 실패다.
  - 각 경로는 `resolve(repositoryRoot, name)` 으로 해석한다. 주어진 순서를 유지하고 정렬하지 않는다 — CI 의 순서는 선언된 것이지 우연이 아니다.
  - 존재하지 않는 경로가 하나라도 있으면 없는 경로를 **전부** 나열하는 메시지와 함께 exit 1. 이것이 shell glob 보다 강한 지점이고, 컴파일이 멈춘 스위트가 조용히 사라지는 대신 빨개지는 이유다.
  - spawn 은 그 외에 바뀌지 않는다: `["--test", ...flags, ...files]`, `cwd: repositoryRoot`, `env: scrubbedEnvironment(process.env)`, `shell: false`, `windowsHide: true`, 그리고 지금의 exit-code / signal 전파.

같은 파일에서 `INJECTED_NAMES` 에 `"init_cwd"` 를 추가한다. 이 Set 은 `name.toLowerCase()` 로 조회되므로 소문자로 넣는다. npm 은 lifecycle child 에만 이 이름을 설정하고 다른 무엇도 설정하지 않으며, 현재 정규식 `^npm_(config|package|lifecycle)_` 은 이 이름에 닿지 않는다. `NODE` 와 `COLOR` 는 **일부러 건드리지 않는다** — npm 네임스페이스가 아니고, 추측으로 scrub 집합을 넓히는 것이 수리를 두 번째 결함으로 만드는 방법이다.

파일 머리 주석에 왜 이 인자가 생겼는지 한 문단을 더한다: CI 의 안전경계 스텝이 이 러너를 우회했고, windows-latest 이미지가 `npm_config_prefix` 를 머신 스코프로 설정했으며, 그래서 1차 게이트가 같은 파일을 도는 CI 스텝보다 더 초록이었다는 사실. 관측된 run id `33984247757` 을 적는다.
