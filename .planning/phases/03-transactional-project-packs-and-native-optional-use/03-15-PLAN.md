<objective>
Stop the suite from being able to prove nothing quietly.

Purpose: `03-VERIFICATION.md` closes its fourth independent check with a recorded observation rather than a
gap. The three tests that start the pinned Context7, Exa and Firecrawl servers and assert their tool SETS —
the last of which is the Pitfall 8 firecrawl regression this phase was built to keep closed — skip on a
registry-unreachable regex over captured upstream stderr. On the verifier's host all three RAN and PASSED and
are not among the suite's six platform skips. The residual risk the verifier named is precise: an air-gapped
CI silently loses the Pitfall 8 regression, and the run still reports green. Its recorded judgement: "Worth a
CI-side assertion that these three did not skip; recorded as an observation, not a gap."

The same section records a second, smaller thing worth knowing: `capability-oracle.test.ts` asserts that no
MCP-coded finding was minted from a recording in which every server is legitimately `pending` — an assertion
that would hold if the finding list were always empty. The verifier called it "Not a gap; worth knowing."
`parseClaudeInitEvent` returns a literal empty finding list today, so the assertion is in fact a regression
guard on a finding path that does not yet exist. That is a fine thing to be; it is not a fine thing to be
silently.

`.github/workflows/pack-skill-drift.yml` is the analog and it already settled the policy question this plan
inherits: a network-touching check fails the run red, deliberately, with the reasoning recorded in the file —
"a check that reports amber on real drift is a check nobody acts on", and a transient upstream fault showing
red was weighed and accepted.

Output: one named environment variable that turns the graceful skip into a loud failure, set by CI and unset
everywhere else; a pure classifier both of whose branches are tested offline; a test binding the workflow to
the helper's own constant; and one assertion that states its precondition.

Explicitly NOT this plan: widening what the three tests assert, adding a new network-touching test, or
running any paid canary.
</objective>

## Flagged planner assumptions

- **GitHub-hosted runners can reach the npm registry.** All three tests ran and passed on the developer's host
  and the three legs already run `npm ci`, so registry reachability is a precondition of the job long before
  these tests. If a hosted leg genuinely cannot reach it, the job was already going to fail at `npm ci`; the
  gate makes it fail for a stated reason instead of passing shorter.
- **The gate is deliberately opt-in and CI is the only opter-in.** A developer on a plane keeps the graceful
  skip with its stated reason. Making the fail-closed behaviour the default would trade a recorded observation
  for a daily annoyance, which is not what the verifier asked for.
- **`capability-oracle.test.ts` line 410 is structurally vacuous, not merely weakly guarded.** The verifier
  described it as holding "if `findings` were always empty" and guarded in practice by the exact counts above
  it. Reading the parser shows the finding list is a literal empty list, so the counts above do not guard it at
  all. Task 2 states that rather than repairing it, because there is nothing broken to repair — the assertion
  is a regression guard and should say so. Raised here because it slightly sharpens the verifier's wording.
