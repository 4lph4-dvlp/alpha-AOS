### CR-02: The complete active authority can still be replaced

**Classification:** BLOCKER  
**Re-review status:** RESOLVED in `aad8664`. `Object.freeze(this)` makes the authority binding non-writable/non-configurable while the nested approval remains frozen. The independent authority regression passed assignment/redefinition rejection.
**File:** `C:/Users/alpha/gsd-workspaces/alpha-aos-computer-use/alpha-AOS/src/core/computer-use.ts:19,32,40-43`  
**Related:** `src/core/computer-use.ts:53,80,87`

**Issue:** Freezing the cloned authority's nested objects does not make the `authority` property on `ComputerSession` non-writable. TypeScript `readonly` is erased. JavaScript callers can assign a different authority after opening the session, and subsequent policy checks and audit policy hashes use that replacement. This defeats the claimed immutable approval snapshot. Native permissions are an additional bound, but they do not enforce all broker fields such as the approved screenshot region.

**Reproduction/evidence:** Opened a fake-transport session with a click-only authority, assigned a validated type-text authority to `session.authority`, then submitted public text. The production broker dispatched once and returned verified. Output: `{"case":"replace-whole-authority","originalAllowed":["click"],"replacedAllowed":["type_text"],"effects":1,"outcome":"verified","writable":true}`. The existing nested-mutation regression does not cover replacement of the property itself.

**Fix:** Store the frozen authority in a private `#authority` slot and have every internal decision use that slot. Expose only a getter without a setter, or a non-writable non-configurable public view. Test both nested mutation and reassignment from JavaScript, including attempted region/budget/run changes; the original authority must govern every later action.

### CR-03: Tampered active journals do not block subsequent native input

**Classification:** BLOCKER  
**Re-review status:** RESOLVED in `aad8664`. The writer compares exact committed bytes; session checks validate journal, referenced captures and pending intents before input and revoke on corruption. Four independent repair regressions passed for same-length rewriting, truncation, appended bytes and corrupt captures, with no later effect.
**File:** `C:/Users/alpha/gsd-workspaces/alpha-aos-computer-use/alpha-AOS/src/core/computer-use-audit.ts:96-103`  
**Related:** `src/core/computer-use.ts:84-90`

**Issue:** `append` compares the current path's size with the same open inode's current size, rather than with an expected committed length/content. An in-place edit, append or truncation updates both observations together. No existing hash chain or capture integrity check runs before the next effect. The broker can append another durable intent and dispatch native input against an already invalid audit history, only discovering corruption during later replay. This is distinct from replacement of an entire journal plus its trusted anchor.

**Reproduction/evidence:** Completed action 1, rewrote `verified` to the same-length `tampered` in the active `events.jsonl`, then executed action 2. Action 2 still dispatched and returned verified; replay against the newly returned anchor rejected the corrupted chain. Output: `{"case":"tampered-active-journal","effects":2,"secondOutcome":"verified","replayRejected":true}`.

**Fix:** Bind the writer to expected committed length and content, and verify the existing journal/capture references against its in-memory trusted checkpoint before allowing another effect. Use an approach that also detects same-length edits, not only inode/size changes. Refuse and revoke the session on detected corruption. Add active-writer tests for same-length rewriting, truncation, appended bytes and prior-capture changes, asserting zero further dispatch.

### CR-04: Failure to record an uncertain effect skips session cancellation

**Classification:** BLOCKER  
**Re-review status:** RESOLVED in `aad8664`. The catch path captures the correct unknown/interrupted outcome and cancels before the fallible fallback append. The independent lost-response plus storage-failure regression passed, including refusal after storage recovery and preservation of the pending intent.
**File:** `C:/Users/alpha/gsd-workspaces/alpha-aos-computer-use/alpha-AOS/src/core/computer-use.ts:101-105`

**Issue:** The catch path awaits the fallback result append before calling `#cancel`. If the native call may have taken effect and audit append/fsync also fails, that await throws and cancellation never runs. The MCP session remains usable. Once storage recovers, another input can execute even though the previous effect has no settled outcome and the code intended to stop on any dispatched error.

**Reproduction/evidence:** Fake native dispatch incremented its effect counter and threw a lost-response error; audit result appends were made to throw a storage failure. After the action rejected, the transport close count was still zero. Restored audit appends and submitted another action: it dispatched and returned verified. Output: `{"case":"failed-result-does-not-revoke","closedAfterFailure":0,"effects":2,"secondOutcome":"verified"}`.

**Fix:** Revoke/cancel immediately whenever a dispatched action enters the error path, independently of whether fallback audit writing succeeds. Put cancellation in a guaranteed `finally` path or before the fallible append; preserve the pending intent and surface both failures without reopening input. Add a regression for native-response failure plus result-storage failure, then restored storage; every later action must refuse with no further effect.

### CR-05: Retention deletes captures still required by recent events

**Classification:** BLOCKER  
**Re-review status:** RESOLVED in `aad8664`. Expiry builds a set of recent references and excludes their hashes from deletion. The independent shared old/recent capture regression passed, retaining readable unexpired PNG bytes.
**File:** `C:/Users/alpha/gsd-workspaces/alpha-aos-computer-use/alpha-AOS/src/core/computer-use-audit.ts:151-158`

**Issue:** Capture blobs are deduplicated by content hash, but expiry selects a hash when any old event references it. It does not check for a newer reference to the same hash. An unchanged screenshot commonly appears in multiple observations. Retaining events newer than the cutoff can therefore delete their still-retained screenshot and mark that recent evidence expired.

**Reproduction/evidence:** Stored one valid PNG, appended two decision events referencing that same capture at times 10 seconds apart, then expired with a cutoff between those times. Retention deleted the PNG despite the second event being newer than the cutoff; replay treated its capture as expired. Output included `{"case":"retention-shared-recent-capture","blobMissing":true,"expired":1}`, with `recentEventAt > cutoff`.

**Fix:** Calculate retention per blob using every reference. Delete only hashes whose most recent referencing event is older than the cutoff and which are not needed by any retained/pending/failed evidence. Preserve deduplication. Add a shared-hash old/new-reference regression that proves the recent capture remains readable and unexpired.
