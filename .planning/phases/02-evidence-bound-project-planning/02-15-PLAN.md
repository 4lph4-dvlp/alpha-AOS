<objective>
Close the four remaining review findings that land on DETC-04's byte stability and DETC-05's refusal
quality, and give the catalog drift check a home.

The heaviest of the four is WR-01, and it contradicts the property this phase was built to have.
`discoverPersonalSkillNames` reads the reviewer's home-directory skill roots on the PREVIEW path; a hit
appends a `SKILL_SHADOWED` approval; `approvals` is folded into `digestablePlan`. Two people reviewing
the identical commit of the identical repository therefore compute different `planDigest` values, and a
digest reviewed on a laptop cannot be approved on CI. The verifier ran on one host and could not see it;
the reviewer found it by reading the digest's inputs.

The other three are smaller and land on the same surfaces: a safe inverse whose guard hash is invented
for bytes that were never read, two module-level caches keyed on nothing so the first caller in a
process decides the catalog for every later one, and a paste-ready command quoted only when the path
contains whitespace.

Purpose: DETC-04 promises stable text and JSON plans and DETC-05 promises a refusal that is a next step
rather than a dead end. A digest that varies by host breaks the first; a command that does not parse
breaks the second.

Output: a host-independent plan digest that still reports the host-specific fact, an honest safe
inverse, root-keyed caches, a paste-safe command, and a scheduled or checklisted drift check.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewer's home directory → plan digest | Host state reaching a value that must depend only on the repository |
| unreadable target bytes → safe inverse guard | An assertion about bytes that were never observed |
| user-supplied path → a command presented as ready to paste | The user's own shell reinterprets what the tool printed |
| npm registry → catalog/lock drift | An unchecked divergence between the declared packs and the pinned hashes |
