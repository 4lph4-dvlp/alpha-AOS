| Boundary | Description |
|----------|-------------|
| GitHub Remote Actions → Local Verification | Remote CI run outcomes and statuses queried via `gh` CLI are parsed strictly and must return positive `conclusion: success` before unblocking or promotion. |
| Candidate Branch → Main Branch | Candidate code stays on `automation/dependency-candidate` until full matrix CI and fixtures pass; no direct unverified merge to `main`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-06 | Tampering / State Desynchronization | git rebase / push | high | mitigate | Rebase onto linear `main` history preserves clean fast-forward semantics and ensures candidate tests run on exact production code. |
| T-13-07 | Elevation of Privilege | scripts/check-main-baseline.mjs | high | mitigate | Red-Main Guard strictly refuses eligibility if `main` CI is red or indeterminate, preventing promotion onto broken commits. |
| T-13-08 | Repudiation | PROMOTION-EVIDENCE.md | medium | mitigate | Concrete Run IDs, commit SHAs, and timestamped job tables provide immutable audit records of CI matrix results. |
| T-13-09 | Denial of Service / CI Flakiness | CI 3-OS Matrix | medium | mitigate | All flaky and race hazards identified in Phase 10 (EBUSY Windows cleanup, timing) were fixed on `main`, ensuring deterministic 1-shot CI pass. |
</threat_model>
