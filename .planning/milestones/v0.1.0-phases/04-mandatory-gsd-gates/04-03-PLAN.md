Create `src/core/gate-lifecycle.ts`:
- Implement `checkReceiptStaleness(receipt: GateReceipt, currentHeadSha: string, currentWorktreeDigest: string): { isStale: boolean; reason?: string }`:
  - If `receipt.targetCommitSha !== currentHeadSha`:
    return `{ isStale: true, reason: "Git HEAD moved from " + receipt.targetCommitSha.slice(0, 8) + " to " + currentHeadSha.slice(0, 8) }`.
  - If `receipt.workingTreeDigest !== currentWorktreeDigest`:
    return `{ isStale: true, reason: "Working tree files in risk surface modified since gate check was run" }`.
  - Otherwise return `{ isStale: false }`.

- Implement `formatGateBlockingFeedback(params: { obligation: string; reason: string; offendingFiles: readonly string[]; engineOutput?: string; recheckCommand: string }): string`:
  - Builds clear alert box:
    ```
    ================================================================================
    🚨 MANDATORY GSD GATE BLOCKED: <OBLIGATION>
    ================================================================================
    Status: <REASON>

    Risk Evidence Detected:
      - <file1>
      - <file2>

    Engine Verification Output:
      <output>

    Action Required:
    To run or re-verify this mandatory gate, execute:
      $ <recheckCommand>

    GSD cannot advance to UAT/verification until this gate passes.
    ================================================================================
    ```

- Implement `evaluateLifecycleGates(projectRoot: string, options?: { explicitBase?: string }): Promise<GateLifecycleResult>`:
  1. Inspect phase diff via `resolvePhaseGitDiff(projectRoot, options)`.
  2. Evaluate risk obligations via `evaluateRiskObligations(diffRange)`.
  3. If `obligationResult.silentPass`:
     return `{ passed: true, silentPass: true, verdicts: [] }`.
  4. Compute current working tree digest for `obligationResult.riskFiles` via `computeRiskSurfaceDigest`.
  5. For each required obligation in `obligationResult.obligations`:
     - Read existing receipt via `readGateReceiptStrict(projectRoot, obligation)`.
     - If receipt is null:
       mark status `"missing"`.
     - If receipt status is `"failed"`:
       mark status `"failed"`.
     - If receipt status is `"passed"`, test staleness via `checkReceiptStaleness`. If stale, mark status `"stale"`.
     - Otherwise mark status `"passed"`.
  6. If any verdict is not `"passed"`:
     - Compose `blockingFeedback` via `formatGateBlockingFeedback` citing offending files and `alpha-aos gate check --obligation <name>`.
     - Return `{ passed: false, silentPass: false, verdicts, blockingFeedback }`.
  7. If all verdicts are `"passed"`, return `{ passed: true, silentPass: false, verdicts }`.
  </action>
  <acceptance_criteria>
    - `checkReceiptStaleness` flags head commit changes and post-check working-tree changes as stale (D-09).
    - `formatGateBlockingFeedback` includes obligation, failure reason, offending files, and runnable recheck command (D-08).
    - `evaluateLifecycleGates` fail-closed blocks any missing, failed, or stale gate (D-07).
  </acceptance_criteria>

     - Flags: `--point <execute:post|verify:pre>`, `--phase <number>`, `--obligation <name>`, `--json`, `--base <ref>`.
     - Resolves project root.
     - First, evaluates current gate state via `evaluateLifecycleGates`.
     - If `--obligation` specified or unverified gates exist:
       - Run check for requested obligation(s) using `selectGateEngine` and `executeGateCheck`.
       - Write resulting gate receipt via `writeGateReceipt`.
       - Re-evaluate lifecycle gate state.
     - If all gates pass (or silent pass):
       - If `--json`: output JSON `{ ok: true, passed: true, silentPass: ..., verdicts: [...] }`.

     - If any gate fails or remains blocked:
       - If `--json`: output JSON `{ ok: false, passed: false, verdicts: [...] }`.
       - Else: output `result.blockingFeedback` formatted banner to stderr.
       - Exit with code 2 (domain refusal / blocked).

     - Flags: `--json`, `--base <ref>`.
     - Inspects current repository state, cumulative diff, and existing gate receipts.

     - Exit with code 0 (or exit 2 if any gate is failing/stale and user requested strict status).
