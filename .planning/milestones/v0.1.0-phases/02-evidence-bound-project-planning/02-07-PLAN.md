<objective>
Make the answer to "why did this pack attach, and why did that one not?" a first-class, uniform,
bounded output — and let the project manifest force any pack on or off with the override recorded as
evidence rather than as a bypass.

Purpose: DETC-03 is the requirement that a generic file alone can never activate an agent-runtime pack,
and that a near-match is explainable. Both die the moment the evaluator short-circuits: the moment an
`any` finds its first true leaf, the information about the other leaves is gone.

Output: the evaluate-all evaluator over the full operator set, near-miss classification with a
deterministic cap, uniform explanation rendering, `--why`, `--project <rel>`, and D-06 pack overrides.
</objective>

Replace the single-operator evaluator in `src/core/project-plan.ts` with a full-tree evaluator over the
operator set the declarations actually use: `all`, `any`, `anyFiles`, `anyDependencies`,
`manifestOptIn`, plus the bounded nesting plan 02-02 added to the schema.

A pack's evaluation is a full tree of leaf results, NOT a boolean. Compute the truth value of every
leaf of every pack, then classify. `Array.prototype.some` short-circuits, which destroys exactly the
information DETC-03 needs — the moment an `any` finds its first true leaf, the reasons the other leaves
failed are gone. Keep both `satisfied: LeafResult[]` and `failed: LeafResult[]`, and populate each
failed leaf's `reason` from the corresponding negative record in the evidence envelope.

Synthesize leaf ids uniformly so every explanation renders from one vocabulary: `dependency:<name>` for
an `anyDependencies` literal, `file:<name>` for an `anyFiles` literal, and the existing `manifest:<key>`
form for `manifestOptIn`. That last spelling already exists in the codebase and the other two extend
it rather than introducing a second convention.

Add the `broad` rule from the fact vocabulary: a pack is not selected when every one of its satisfied
leaves names a fact marked `broad`. This is the mechanical form of the rule that a generic file alone
never activates an agent-runtime pack. It is not a special case for one pack — a bare source directory
satisfies the browser-entrypoint fact just as readily, and is safe today only because its pack's `all`
also demands a framework dependency. Making the rule general removes that accident.

Classify each pack into `selected`, `near-miss`, `silent`, or `unimplemented`. `unimplemented` covers a
pack whose predicate names a fact the vocabulary declares with `deferredTo` and no detector parameters
— the eight risk facts under the security pack. Its record must name the offending fact ids and the
requirement they are deferred to, so the output is honest rather than silent. Plan 02-02's load-time
`domain.undeclared-fact` refusal covers a fact that is not declared AT ALL; this classification covers
a fact that is declared as deliberately unimplemented. Keep the two distinct.

This resolves the CONTEXT discretion item on which packs ship: fourteen of fifteen ship fully, and the

Define near-miss as: at least one leaf of the pack's predicate is satisfied AND at least one is not.
Under `all` that is a genuine partial match. Under `any`, no satisfied leaf means the pack matched
nothing and stays silent; a satisfied leaf would have selected it — so an `any`-only pack is never a
near-miss, which is correct because there is nothing to explain. For a nested composition, apply the
rule to the flattened leaf set.

Bound the default output at a named `MAX_NEAR_MISS_LINES` constant with the recommended value 5,
ordered by descending satisfied-leaf count then ascending pack id as a deterministic tiebreak, with a
trailing line naming how many further packs are suppressed and pointing at `--why`. This mirrors the
existing validation-issue discipline: deterministic order and a hard cap, so a hostile document cannot
flood output. `--why` prints all 15 with full leaf detail.

Render both phrases from the fact vocabulary's `description`, never from a per-pack hand-written
string, so all 15 packs explain uniformly. The required line shape, from the CONTEXT's specific ask, is
the pack id followed by what was found and then what was missing — the worked example being an
agent-runtime pack where the generic instructions document is present but the agent SDK dependency is
not. A generic file that exists in ordinary repositories must never be sufficient on its own, and the
explanation must make that VISIBLE rather than merely true.
