## Why the EACCES fixture can be unprivileged, stated concretely

The branch under test needs `lstat` to SUCCEED and `realpath` to FAIL with a non-ENOENT errno. A directory with mode `0o000` does not produce that directly — `lstat` on a path *beneath* it fails with EACCES, and `classifyComponent` turns an EACCES from `lstat` into `unknown-reparse`, which is a different code and a different fact.

The shape that reaches the intended branch is a **directory link pointing into an unreadable directory**:

- `<allowed>/blocked/` with mode `0o000`, containing `inner/` created before the mode change.
- `<allowed>/link` → `<allowed>/blocked/inner`, an ordinary directory symlink.
- `lstat("<allowed>/link")` succeeds (the link itself lives in a readable directory), `readlink` succeeds, so the component is classified as a link — and then `realpath("<allowed>/link")` must traverse `blocked` and fails with EACCES. That is `classifyComponent`'s `unprovable` branch at `:200-207`.
- Naming `<allowed>/link` as the **allowed root** instead reaches `canonicalizeWithMissingTail` at `:296-299`, whose components are never classified, which is the other half of the branch.
- Building the proof while `blocked` is still readable, then changing the mode, then calling `recheckPathProof`, reaches `:352-355`.

An ordinary unprivileged user owns the directory and can set its mode, so this runs on ubuntu-latest and macos-latest without privileges. It does **not** work as root (root ignores the mode) and it does **not** work on Windows (a POSIX mode does not deny traversal there), so it is gated — and the gate probes the host rather than trusting a platform name.
