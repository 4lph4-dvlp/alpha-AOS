<objective>
Close the phase with the reconciliation that makes an installed pack's state legible: what is still
current, what drifted, what became stale and exactly which fact disappeared — and a removal path that
requires a human approval rather than deleting anything on its own.

Purpose: the failure this exists to prevent is a user being told a pack is stale and being unable to
tell whether the dependency was removed, the branch changed, or the file simply became unreadable. Three
different causes must not produce identical text.

Output: `alpha-aos project status` with receipt-by-evidence reconciliation, the fact-naming `STALE`
line, the offline branch context, and the approval-gated removal plan.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.alpha-aos/plan.json` and `.alpha-aos/receipts/` → status | Repository-local files a hostile or simply stale checkout can contain. |
| `.git` directory → branch context | Untrusted text read from the repository, on an offline path. |
| removal plan → filesystem deletion | The only destructive operation this phase can describe. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08 | Spoofing | `.alpha-aos/plan.json` as an authority | high | mitigate | `status` recomputes evidence and reports a mismatched artifact as `CHANGED`; a planted artifact claiming unsupported packs is never honoured. |
| T-02-35 | Tampering | the removal path | high | mitigate | Stale evidence never triggers deletion; a removal plan is built at read time, requires approval through the existing digest contract, and executes only through the journaled snapshotted transaction whose snapshot is the safe inverse. |
| T-02-23 | Spoofing | an unreadable evidence file | high | mitigate | Classified `UNDECIDABLE` with the errno and path; it is never `STALE`, so a permission error can never be mistaken for evidence that is gone — and therefore never motivates a removal. |
| T-02-22 | Denial of Service | `readGitContext` | medium | mitigate | Byte-capped reads of `.git/HEAD`, the loose ref, and `packed-refs`; an unparseable state reports unavailable rather than looping or guessing. |
| T-02-15 | Denial of Service | subprocess on the status path | medium | mitigate | The branch context is read from the filesystem; no `git` subprocess runs, keeping `plan`, `approve` and `status` offline and subprocess-free. |
| T-02-24 | Repudiation | branch context in a digest | high | mitigate | Branch and commit are context only and are excluded from all three digests, asserted by a test that commits an irrelevant change and observes every digest unchanged. |
| T-02-11 | Tampering | `project status` write surface | high | mitigate | Registered in the SAFE-01 `PREVIEW_INVOCATIONS` enumeration; the whole reconciliation is asserted to leave the fixture tree byte-identical. |
