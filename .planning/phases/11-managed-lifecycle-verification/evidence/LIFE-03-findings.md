## Core clause

The core promise is: remove alpha-AOS-managed state without removing unrelated user resources. Its safety half holds for the target and full-stack uninstalls (authentication, user MCP entries, user skills and the other harnesses are untouched on all five harnesses), and for the approve-route pack removal. It fails in two ways:

- `uninstall --project` removes a user note and the user-reviewed `.alpha-aos/stack.yaml`, and it removes no pack target (LIFE-03/C3).
- No uninstall scope removes the alpha-AOS-owned skills. `alpha-aos-control` stays on all five harnesses and `alpha-aos-ship` stays on claude. The full-stack uninstall also leaves `claude/settings.json` and isolated runtimes (LIFE-03/C1, C5). `uninstall --target pi` also takes codex's ECC skills (LIFE-03/C2).

Result: VIOLATED.

## Provisional verdict

GAP (D-02): the core promise is not met. `uninstall --project` removes user resources, and the one-target and full-stack uninstalls leave alpha-AOS-owned files on every harness. The previews, the isolated-runtime clean, the approve-route pack removal, the confirmation guard and the preservation of harness applications, authentication and user MCP/skill entries all hold.

It is inside alpha-AOS's own state root and no user resource is shown removed, so this is recorded only as an observation (plan 11-04 step 3).
- Each file pruned or removed by `uninstall` is its own transaction: 12 journals before `uninstall --all`, 31 after (`life03.all.journals-kept HOLDS`). The uninstall is therefore reversible per file, but not as one operation.
- Under WSL the npm 12 CLI prints `npm pack --json` as an object keyed by package name instead of an array. The TTY probe packs the tarball itself for that reason (life03-tty.txt step 1). `packRelease` in `test/helpers/packed-sandbox.ts` and `packOnce` in `probe-lib.mjs` accept only the array shape, so a CI runner that moves to npm 11+ would fail there first. This belongs to the test harness, not to LIFE-03.
- The `web` domain's removal needs the `public/` directory deleted, not just `public/index.html`, because `browser-entrypoint` is a directory fact (`catalog/facts.yaml`). With only the file deleted, status keeps WEB_BASE `CURRENT` and offers no removal. This is consistent with the declared fact.
