<objective>
Split "what was looked at" from "what was approved", and make an apply refuse the moment anything a
reviewer saw has moved.

Purpose: DETC-05 is exactly the reviewed-digest contract Phase 1 already implements for the ECC, GSD,
MCP, isolation and support-bundle components. Building a second drift mechanism would guarantee the two
drift apart. The work here is binding the project plan into that contract and making the refusal
INFORMATIVE — D-13 says the refusal is not a dead end.

Output: `approveProjectPlan`, the `alpha-aos project approve` CLI verb, the `.alpha-aos/plan.json`
artifact written under one transaction, and the D-13 refusal split.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewed plan → applied plan | Everything a reviewer saw can change between the two acts; the digest is what makes that detectable. |
| `approve` → project filesystem | The first Phase 2 code that writes anything into a user's repository. |
| concurrent invocations → the artifact | Two writers against one file. |

| T-02-31 | Tampering | the write surface of `approve` | high | mitigate | `applyFileTransaction` with `allowedRoots` limited to the project's `.alpha-aos` directory and paths proven up front; project source, package manifests, tests and build configuration are read-only and asserted byte-identical by the fixture snapshot. |
