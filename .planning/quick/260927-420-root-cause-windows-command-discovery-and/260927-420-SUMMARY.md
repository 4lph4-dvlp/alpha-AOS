# Root-cause repair of Windows discovery and fixture lifecycle

The failed Windows CI was investigated through alpha-AOS diagnostics and a GSD debug record, with independent native experiments before repair. The structured reasoning checkpoint, competing hypotheses, negative results, selected/rejected options and recurrence guards are in [the resolved investigation](../../debug/resolved/windows-process-lifecycle.md).

## Findings and implementation

1. Timed locator failure was reported as executable absence. A delayed native locator returned ETIMEDOUT for an existing executable while the baseline API returned null. Commit `698efd7` replaces the Windows locator subprocess with current/PATH/PATHEXT candidate discovery, preserving native executable preference. A native regression finds and invokes a binary with where.exe unavailable. Commit `75ebbd4` also distinguishes POSIX locator failure, abnormal exit and signals from genuine absence.
2. The failed CI's tree oracle explicitly reports esrch/terminated=true immediately before recursive removal returns EBUSY. Commit `b04f0a6` allows only proven termination to enable a finite Windows handle-release cleanup budget. This models filesystem availability separately from liveness. The historical busy-handle owner was not captured and is not claimed as known.
3. A delayed-PID experiment proved a separate test coverage hole: missing PID previously returned without an assertion. It now fails explicitly. Operation and termination deadlines, concurrency and required upstream gates remain unchanged.
