## Gap being closed

`01-UAT.md` gap `G-01-1`, root cause **RC-3**, `missing` items 6 through 13. The debug session `.planning/debug/uat-safety-boundary-parallel.md` reproduced it deterministically on this Windows host by removing `LOCALAPPDATA`, which forces npm's cache to be home-derived exactly as it is on POSIX:

> control (normal env) -> PASS; `env -u LOCALAPPDATA` -> FAIL, "preview of `install` mutated an observable surface". before home = `97742fbe…`, which is BYTE-IDENTICAL to the ubuntu CI `expected` digest.

And directly, without a test in the way:

> `alpha-aos install --target claude` (exit 0, no `--apply`) — home gained `npm-cache/_logs/2026-09-05T13_11_25_887Z-debug-0.log`. The log's own header records `verbose title npm root` / `verbose argv "root" "--global"`.

Two things follow, and this plan does both. The product must stop spawning that probe from a plan builder. The oracle must stop depending on an inherited environment variable for its verdict — that dependence is the exact defect being fixed, so a suite that passes only because the runner injected `npm_config_cache` is not evidence of anything.

**Ordering matters and is not negotiable.** Task 1 makes the primary gate and the CI step agree. Task 2 hardens the oracle and only then fixes the product, so the green at the end of Task 2 is caused by the product change and not by the oracle change. Task 3 pins the remaining surface. Do not reorder.
