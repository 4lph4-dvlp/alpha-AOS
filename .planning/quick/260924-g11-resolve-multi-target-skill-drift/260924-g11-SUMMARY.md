## 1. Problem Overview & Root Cause

### Problem
When executing a combined managed install across multiple harnesses that share skill destinations (specifically `codex` and `pi`, which both target `<home>/.agents/skills/alpha-aos-control/SKILL.md` for owned skills and `<home>/.agents/skills/` for ECC universal skills):
- The first target (`codex`) applied its skill files to disk.
- When the second target (`pi`) ran within the same transaction session, its pre-apply step verification compared the current disk state against the planning-time snapshot/hash.
- Because the first target had already created the file on disk during the ongoing operation, the second target rejected the state with `ComponentPlanError("plan-drift")`.

This gap (`G-11-1`, identified under `LIFE-01` in the Phase 11 verification report) was the primary blocker for Phase 13 dependency candidate promotion under constraint `D-08`.

### Secondary Issue Discovered
In `src/core/install.ts`, `probeGlobalNpmPackageVersion` invokes `npm root --global` through `runProcess`. `runProcess` redacts temporary paths to `<temp>`, and `expandAliasedPath` only expanded `~`, failing to expand `<temp>` and `<state>` back to actual filesystem paths. When running inside temporary prefix directories, this caused `probeGlobalNpmPackageVersion` to fail finding package manifests.

---

## 2. Changes Made

### 1. Destination and Root Deduplication in `applyManagedInstall` (`src/core/install.ts`)
- Added `writtenDestinations = new Map<string, string>()` tracking `destination -> expectedHash` for owned skills.
  - Before applying an owned skill, checks if the destination was already written in the current transaction.
  - If already written: verifies that the expected hash matches, and marks the step as satisfied (`operationId: null`) without redundant disk writes or invoking `applyOwnedSkillSync`.
- Added `writtenEccRoots = new Set<string>()` tracking target roots for ECC skills.
  - Before applying ECC skills, checks if the target root has already been synchronized in the current transaction.
  - If already written: marks the step as satisfied (`operationId: null`) without invoking `applyEccSkillSync`.

### 2. Path Alias Expansion (`src/core/install.ts`)
- Updated `expandAliasedPath` to support:
  - `<temp>` and `<temp>/` / `<temp>\` -> expanded using `tmpdir()`.
  - `<state>` and `<state>/` / `<state>\` -> expanded using `process.env.ALPHA_AOS_STATE_DIR` (when set).
- Ensures that `probeGlobalNpmPackageVersion` correctly restores absolute paths from child process excerpts under sandboxed npm prefixes.

### 3. Regression Test Suite (`test/owned-skills.test.ts`)
- Added comprehensive unit test: `"applyManagedInstall succeeds on combined codex and pi install without plan-drift on shared destination (G-11-1)"`.
- Validates:
  - Preview plan includes both `codex` and `pi` owned-skill steps with action `create`.
  - First combined apply across `["codex", "pi"]` completes in one transaction: `codex` applied, `pi` satisfied as current, no `plan-drift` error.
  - Shared skill file `<home>/.agents/skills/alpha-aos-control/SKILL.md` is present on disk.
  - Second combined apply (reconcile) reports `applied: []`, `operationIds: []`, and all steps `current`.
