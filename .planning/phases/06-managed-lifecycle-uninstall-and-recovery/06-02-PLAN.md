     `"status": { "enum": ["applying", "applied", "rolled-back", "failed", "repaired"] }`

   - Update TypeScript interface `TransactionJournal`:
     `status: "applying" | "applied" | "rolled-back" | "failed" | "repaired";`
     `repairedAt?: string;`

3. In `src/types.ts`:
   - Export `CrashRepairAction`, `CrashRepairPlan`, `CrashRepairResult`.

4. Create `src/core/repair.ts`:
   - Implement `planCrashRepair(stateRoot: string): Promise<CrashRepairPlan>`:
     - Inspect `writer.lock`: read lock record if present.
     - If PID is present, perform ESRCH check via `process.kill(pid, 0)`:
       - If process exists or returns `EPERM`: `writerAlive = true`, add blocked reason `"writer process <pid> is still active; repair refused"`.
       - If error code is `ESRCH`: `writerAlive = false`, lock is classified as stale and eligible for release.
     - Scan `~/.alpha-aos/journal/` for interrupted transactions (`status === "applying"`):
       - If unreadable JSON found: plan `action: "quarantine"`.
       - If incomplete journal found:
         - Inspect `~/.alpha-aos/snapshots/<id>/`.
         - For every file in `journal.files`, check whether `file.snapshot` exists and is readable.
         - If all required snapshots exist: plan `action: "snapshot-rollback"`.
         - If snapshots are missing or corrupt: plan `action: "quarantine"`.
     - If no interrupted journal exists and stale lock exists: plan `action: "release-only"`.
     - Compute deterministic `planDigest` over plan fields.
   - Implement `applyCrashRepair(stateRoot: string, reviewedPlanDigest: string): Promise<CrashRepairResult>`:
     - Recompute plan and verify `plan.planDigest === reviewedPlanDigest`.
     - If `action === "snapshot-rollback"`:
       - Restore all touched files from `snapshots/<id>/` back to their original target paths (`beforeHash`).
       - For files that did not exist before (`existed === false`), unlink them.
       - Update journal: set `status = "repaired"`, set `repairedAt = new Date().toISOString()`.
       - Flush updated journal.
       - Delete `writer.lock`.
     - If `action === "quarantine"`:
       - Quarantine the corrupt journal: rename file to `~/.alpha-aos/journal/<id>.corrupt.<timestamp>`.
       - Delete stale `writer.lock`.
       - Return result with `quarantinedJournal` path.
     - If `action === "release-only"`:
       - Delete stale `writer.lock`.
   - Implement helper `quarantineJournal(journalPath: string): Promise<string>`.

5. In `src/format.ts`:
   - Export `formatCrashRepairPlan(plan: CrashRepairPlan): string` and `formatCrashRepairResult(result: CrashRepairResult): string`.

6. In `src/cli.ts`:
   - Update `command === "repair"` to invoke `planCrashRepair` / `applyCrashRepair`.
   - In dry-run mode (without `--apply`): print diagnosis, snapshot status, and guidance.
   - With `--apply`: execute repair and report restored baseline or quarantined file.

7. Create `test/repair.test.ts`:
   - Test 1: Snapshot baseline recovery (`LIFE-06`, `D-10`). Use failpoint fixture `ALPHA_AOS_FAILPOINT=after-target-rename` to leave an interrupted transaction. Run `alpha-aos repair --apply`; assert target files are restored to their exact pre-crash baseline, journal status is `"repaired"`, and `writer.lock` is removed.
   - Test 2: Active writer refusal (`LIFE-06`, `D-12`, `SAFE-03`). Spawn a mock background worker process holding `writer.lock`. Run `planCrashRepair`; assert `writerAlive: true`, `action: "none"`, and repair is refused.
   - Test 3: Stale lock recovery on ESRCH (`LIFE-06`, `D-12`). Kill the worker process (`SIGKILL`). Run `planCrashRepair`; assert `writerAlive: false` and lock is safely released.
   - Test 4: Corrupt journal quarantine (`LIFE-06`, `D-11`). Write a malformed JSON file into `~/.alpha-aos/journal/`. Run `alpha-aos repair --apply`; assert corrupt journal is renamed to `<id>.corrupt.<timestamp>`, stale lock is removed, and diagnostic directs user to verify with `doctor`.
  </action>
